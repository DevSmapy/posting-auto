lock / pid를 헤더에

      
_read_lock()은 pid dead면 lock을 버립니다. P0는 JSON을 항상 읽고 pid_alive를 따로 둡니다. 7200s reclaim은 다음 런용이라 STATUS에 안 씁니다.

      

        

          
live

          
pid=18422 ✓    started 06:00:22

          
프로세스는 살아 있음. hang 여부는 age로.

        

        

          
dead leftover

          
pid=18422 dead

          
lock 파일만 남음. 이건 RUNNING이 아닙니다.

        

      

    


    

      
기다려야 하나?

      

pid alive?

├─ yes → last event/artifact age?

│         ├─ < stage threshold     → 대기. STATUS RUNNING. 배너 없음.

│         ├─ ≥ stale (Publish 10m) → 대기하되 의심. ! STALE?

│         └─ ≥ hang  (Publish 30m) → 수동 확인. ! SUSPECT HANG

└─ no  → monitor.ended?

          ├─ yes → COMPLETE / FAILED (오늘과 동일, reason 우선)

          ├─ lock 있고 pid dead → FAILED (draft 포함)

          ├─ draft & lock 없음 → RUNNING (Approve 대기)

          └─ no  → FAILED  Reason: ended missing (no live lock)
      

      
activity age = min(last_event_age, last_artifact_age). PNG가 늘어나면 event가 없어도 stale이 풀립니다.

  1. 라이브 hang: STATUS는 RUNNING. 둘째 줄 배너 ! STALE? / ! SUSPECT HANG  {n}m since last event.
    2. 
          
  2. 좀비: ended 없을 때 — lock 있고 pid dead면 FAILED (draft 포함). lock 없을 때만 draft는 RUNNING, non-draft는 FAILED. reason은 _fail_reason 우선, 없으면 ended missing (pid dead) / ended missing (no live lock).
    3. 
          
  3. pid: 헤더에 pid=N ✓ 또는 pid=N dead. dead lock JSON은 버리지 않음.
    4. 
          
  4. Publish strip: MD Cards Guard R2 IG. 채널 3행은 유지. emit 없음.
    5. 
          
  5. stale 입력: event timestamp와 artifact mtime 중 더 최근. Publish hang 임계 30m.
